PR Summary

Serialise webhook deliveries per repository so concurrent pushes stop overwriting each other.

✨ Enhancement 🐛 Bug fix 🧪 Tests 🕐 20-40 Minutes

Description

Concurrent deliveries for the same repository overwrote each other's processing state: two pushes seconds apart produced a single comment, the other silently lost. Processing is now serialised per repository, behind a lock held for the duration of the handler.

The trade-off is added latency on busy repositories — two simultaneous deliveries for the same repo now wait instead of racing.

Which issue(s)
  • Closes #128 — duplicate pushes produce a single review comment
  • Related to #96 — the dropped delivery was first seen in the activity log
PR acceptance criteria
  • Two pushes within one second on the same repository produce two comments
  • Deliveries for different repositories still run in parallel
  • A handler exception releases the lock
  • Lock wait time is logged
How to test changes
  1. docker compose up
  2. Push twice within a second to a connected sandbox repository
  3. GET /api/dashboard/activity — both deliveries appear, both completed
Special notes to the reviewer
  • The lock is per repository, not global. Two repositories still run in parallel — if global serialisation was intended, this is not it.
  • retry_after moves from 5s to 30s by default. Callers relying on fast retries will back off six times longer.
